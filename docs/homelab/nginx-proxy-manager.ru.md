# 🔀 Nginx Proxy Manager (приватный HTTPS для всего)

Порты и IP-адреса не масштабируются. `http://192.168.1.20:8096` работает для одного сервиса; к десятому это уже игра на память, каждый браузер кричит «Не защищено», и нигде нет TLS.

Обратный прокси решает всё разом: **одна точка входа, настоящий HTTPS, чистые имена** — `https://jellyfin.home.example.com` — без единого порта, открытого в интернет.

---

## ⚠️ Основной принцип

> Каждый сервис получает имя и сертификат. Никто не получает номер порта в адресной строке.

---

## 🧭 Как всё складывается вместе

```text
Браузер (в tailnet)
   │
   ▼  «jellyfin.home.example.com?»
Локальный DNS (AdGuard Home)  →  отвечает IP-адресом вашего сервера
   │
   ▼  HTTPS :443
Nginx Proxy Manager  →  терминирует TLS, маршрутизирует по hostname
   │
   ▼  Сеть Docker
Контейнер Jellyfin :8096
```

Три компонента:

1. **Настоящий домен в вашей собственности** (несколько долларов в год) — используется исключительно для имён и сертификатов; публично на нём ничего не размещается
2. **Локальный DNS**, отвечающий за него внутри вашей сети — в этом руководстве AdGuard Home
3. **NPM**, терминирующий TLS и маршрутизирующий по hostname

> Именно реальность домена делает возможными настоящие сертификаты; никаких предупреждений о самоподписанных сертификатах и импорта CA на каждое устройство.

## 📦 Стек NPM

Следуя [структуре homelab](docker-home-lab.md), `/opt/stacks/npm/compose.yaml`:

```yaml
services:
  npm:
    image: jc21/nginx-proxy-manager:latest
    container_name: nginx-proxy-manager
    restart: unless-stopped
    ports:
      - "80:80"            # HTTP (перенаправляет на HTTPS)
      - "443:443"          # HTTPS
      - "127.0.0.1:81:81"  # админ-панель — только localhost, доступ через Tailscale/SSH
    volumes:
      - /opt/data/npm/data:/data
      - /opt/data/npm/letsencrypt:/etc/letsencrypt
    networks:
      - proxy

networks:
  proxy:
    external: true
```

Создайте общую сеть один раз и запустите стек:

```bash
docker network create proxy
cd /opt/stacks/npm
docker compose up -d
```

!!! warning "Привяжите админ-панель к localhost"

    Привязка `127.0.0.1:81:81` означает, что админ-панель недостижима из сети —
    даже из вашей LAN. Доступ к ней — через Tailscale или SSH-туннель.
    Панель, управляющая всей вашей маршрутизацией, должна быть самой труднодоступной
    вещью, а не самой лёгкой.

### Первый вход

Откройте `http://server:81` (через Tailscale) и войдите с учётными данными NPM по умолчанию:

```text
Email:  admin@example.com
Пароль: changeme
```

Смена учётных данных потребуется сразу же. Используйте менеджер паролей.

## 🕸️ Общая прокси-сеть

NPM маршрутизирует к контейнерам **по имени через общую сеть Docker** — самим сервисам публиковать порты не нужно.

Добавьте сеть `proxy` в любой стек, до которого NPM должен дотягиваться:

```yaml
services:
  jellyfin:
    # ...существующая конфигурация...
    networks:
      - default
      - proxy

networks:
  proxy:
    external: true
```

Теперь NPM достигает `jellyfin:8096` напрямую, и вы можете **полностью убрать опубликованные порты сервиса** — прокси становится единственной дверью.

> Меньше опубликованных портов = меньше поверхность атаки = меньше поводов для раздумий. Прокси-сеть — это коридор homelab; ключи от входа есть только у NPM.

## 🔐 Wildcard-сертификат без открытых портов (DNS-01)

Обычный поток Let's Encrypt (HTTP-01) требует порт 80, открытый в интернет — ровно то, чего эта конфигурация делать отказывается. Челлендж **DNS-01** доказывает владение доменом через DNS-запись, поэтому работает при полностью закрытых портах. Бонус: это единственный тип челленджа, способный выпускать **wildcard**-сертификаты.

### 1. Создайте API-токен DNS

У вашего DNS-провайдера (показан Cloudflare; NPM поддерживает десятки):

- **My Profile → API Tokens → Create Token**
- Шаблон: *Edit zone DNS*
- Ограничьте область действия **только** нужной зоной (например, `example.com`)

### 2. Запросите сертификат в NPM

**SSL Certificates → Add SSL Certificate → Let's Encrypt**

- Доменные имена: `*.home.example.com` и `home.example.com`
- ✅ *Use a DNS Challenge* → провайдер: Cloudflare → вставьте токен
- Согласитесь, сохраните. Выпуск занимает минуту-другую.

Один wildcard-сертификат теперь покрывает каждый сервис, который вы когда-либо добавите под `*.home.example.com` — без выпуска на каждый сервис, с автоматическим продлением.

!!! tip "Держите приватные имена вне публичного DNS"

    С wildcard-сертификатом отдельные hostname (`jellyfin.`, `paperless.`,
    `vault.`) нигде публично не появляются — ни в вашей DNS-зоне, ни в журналах
    Certificate Transparency, которые фиксируют каждый выпущенный сертификат и
    доступны для поиска любому желающему. Отдельный сертификат для
    `vault.home.example.com` объявляет всему миру, что у вас работает хранилище
    паролей. Wildcard не объявляет ничего.

## 🧭 Локальный DNS с AdGuard Home

Интернет понятия не имеет, что такое `jellyfin.home.example.com` — знать это должна только ваша сеть. В AdGuard Home:

**Filters → DNS rewrites → Add DNS rewrite**

```text
Домен: *.home.example.com
Ответ: 192.168.1.10        # LAN-IP вашего сервера
```

Одна wildcard-перезапись покрывает все нынешние и будущие сервисы.

!!! tip "Заставьте это работать и через Tailscale"

    Направьте перезапись на **Tailscale-IP** сервера (`100.x.y.z`) вместо LAN-IP
    и назначьте AdGuard Home DNS-сервером вашей tailnet (консоль администратора
    Tailscale → DNS → добавьте свой экземпляр AdGuard, включите *Override local
    DNS*). Теперь `https://jellyfin.home.example.com` работает одинаково и дома,
    и через [tailnet](tailscale.md) — один URL везде, блокировка рекламы в комплекте.

## 🔀 Создание proxy hosts

Награда за каждый сервис. **Hosts → Proxy Hosts → Add Proxy Host**:

**Вкладка Details**

```text
Domain Names:         jellyfin.home.example.com
Scheme:               http
Forward Hostname/IP:  jellyfin        ← имя контейнера в прокси-сети
Forward Port:         8096
Websockets Support:   ✅
Block Common Exploits: ✅
```

**Вкладка SSL**

```text
SSL Certificate:  *.home.example.com   ← тот самый wildcard
Force SSL:        ✅
HTTP/2 Support:   ✅
```

Сохраните. `https://jellyfin.home.example.com` работает — вместе с замочком.

Повторите для каждого сервиса; на каждый уходит тридцать секунд:

| Сервис | Перенаправлять на |
| :--- | :--- |
| Immich | `immich-server:2283` |
| Paperless | `paperless-webserver:8000` |
| Forgejo | `forgejo:3000` |
| Uptime Kuma | `uptime-kuma:3001` |

!!! tip "Websockets: просто оставьте включённым"

    Половине homelab (Jellyfin, Uptime Kuma, Dozzle, Home Assistant, всё с
    обновляющимся в реальном времени интерфейсом) нужны websockets, а симптом
    при их отключении сводит с ума своей расплывчатостью — страницы загружаются,
    но ничего не обновляется. Включите по умолчанию и больше никогда это не
    отлаживайте.

## 🛡️ Чек-лист усиления защиты

- Админ-панель привязана к `127.0.0.1`, доступ только через [Tailscale](tailscale.md)
- **Force SSL** на каждом proxy host; добавьте **HSTS**, когда будете уверены в продлении сертификата
- **Block Common Exploits** включён для каждого хоста
- Сайт по умолчанию (Settings → Default Site) настроен на 404 — неизвестные hostname, попавшие на прокси, не узнают ничего
- Убирайте опубликованные порты у сервисов, как только их proxy host заработает
- Данные NPM лежат в `/opt/data/npm` — они уже покрыты [стратегией резервного копирования](backup-and-recovery.md); их потеря означает пересоздание каждого хоста вручную

## 🧰 Устранение неполадок

- **502 Bad Gateway** → NPM не может достучаться до цели. Сервис в сети `proxy`? Hostname перенаправления — это точное **имя контейнера**? Порт — *внутренний* (собственный порт контейнера, а не опубликованное сопоставление)?
- **DNS-челлендж не проходит** → неверная область действия API-токена или задержка распространения — повторите один раз, затем перепроверьте права токена. Логи NPM (`docker logs nginx-proxy-manager`) показывают фактическую ошибку certbot.
- **Имя не резолвится** → клиент не использует AdGuard для DNS. Проверьте, какой резолвер устройство использует на самом деле (`nslookup jellyfin.home.example.com`); телефонам в мобильной сети нужна описанная выше настройка DNS в Tailscale.
- **Цикл перенаправлений** → бэкенд-приложение тоже принудительно включает HTTPS. Установите базовый URL приложения на проксируемый `https://`-адрес или перенаправляйте со схемой `https`, если приложение само обслуживает TLS.
- **Работает в LAN, мертво через Tailscale** → DNS-перезапись указывает на LAN-IP. Используйте в качестве ответа перезаписи Tailscale-IP (достижимый из обоих контекстов).

## 🚫 Чего не делать

- Не пробрасывайте порты 80/443 на роутере «чтобы упростить сертификаты» — DNS-01 существует именно для того, чтобы этого не делать
- Не используйте `.local`, `.lan` или выдуманный TLD — будете бороться с конфликтами mDNS и никогда не получите настоящие сертификаты; реальный домен стоит меньше чашки кофе в месяц
- Не открывайте админ-панель (`:81`) за пределы localhost/Tailscale
- Не проксируйте админ-панели инфраструктуры (Portainer, Dockge, сам NPM) с той же беспечностью, что и медиаприложения — плоскости управления инфраструктурой заслуживают более строгого доступа, а не более красивых URL

## 🧠 Финальная мысль

Обратный прокси — то место, где куча контейнеров начинает ощущаться как **инфраструктура**: именованная, зашифрованная, единообразная, доступная одинаково с дивана и с другого континента.

> Одна дверь. Все сервисы за ней. Ничего не выставлено наружу.
