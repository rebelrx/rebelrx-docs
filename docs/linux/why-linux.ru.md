# 🐧 Почему Linux

Большинство людей не выбирают операционную систему.

Её выбирают *за них*.

* Windows → привязана к учётной записи Microsoft и телеметрии
* macOS → привязана к экосистеме и железу Apple
* Мобильные ОС → полностью закрытые, привязанные к личности платформы

Linux — другое дело.

> Linux — единственная крупная операционная система, которая всё ещё позволяет отказаться от всего этого.

## ⚔️ Почему выбирают Linux

### 🔐 Контроль

Linux даёт вам полную власть над:

* Конфигурацией системы
* Установленным программным обеспечением
* Поведением сети
* Политикой обновлений

Никаких принудительных обновлений.
Никаких обязательных учётных записей.
Никаких скрытых процессов, которые нельзя изучить.

> Администратор — вы, а не вендор.

---

### 🧱 Прозрачность

Linux — открытое ПО.

Это значит:

* Код можно изучать
* Поведение можно проверять
* Бэкдоры труднее спрятать в таком масштабе

Сравните с:

* Windows → закрытая, непрозрачная
* macOS → частично открытая, в основном контролируемая

---

### 🚫 Никакой навязанной экосистемы

Современные платформы операционных систем (ОС) всё сильнее:

* Привязаны к учётным записям
* Зависят от облака
* Связаны с личностью пользователя

Linux позволяет:

* Запускать полностью автономные системы
* Избегать привязки к учётным записям
* Пользоваться своей машиной без внешней валидации

---

### ⚡ Эффективность

Системы на Linux, как правило:

* Быстрее
* Менее требовательны к ресурсам
* Стабильнее на длинных дистанциях

Особенно если избегать раздутых конфигураций по умолчанию.

---

## ⚖️ Компромисс

Linux не «бесплатен» в том смысле, в каком думают люди.

Вы обмениваете:

| Удобство | Контроль |
| ------------------ | -------------- |
| Приложения «включил и работает» | Ручная настройка |
| Поддержка вендора | Самостоятельность |
| Привычный интерфейс | Кривая обучения |

> Linux вознаграждает тех, кто готов разобраться в своей системе.

## 🧠 Основные понятия (глоссарий)

Прежде чем устанавливать Linux, стоит понять несколько ключевых терминов.

---

### 🧬 Ядро (kernel)

Ядро — это сердцевина операционной системы.

Оно находится между:

* Вашим оборудованием (CPU, RAM, диск, GPU)
* Вашим программным обеспечением (приложения, сервисы)

Ядро Linux отвечает за:

* Взаимодействие с оборудованием
* Управление процессами
* Управление памятью
* Границы безопасности системы

> Всё в Linux в конечном счёте проходит через ядро.

Это важно, потому что:

* Все дистрибутивы Linux разделяют **одну и ту же основу — ядро**
* Разница между дистрибутивами — во всём, что *вокруг* ядра

---

### 💻 CLI (интерфейс командной строки)

Текстовый способ взаимодействия с системой. Его также называют «терминалом».

Вместо кликов:

* Вы вводите команды
* Вы управляете системой напрямую из текстового терминала

Пример:

```bash
ls
cd /home
cp file.txt backup.txt
```

Все современные ОС поставляются со встроенным CLI. Возможно, вы даже не знали, что он есть в Windows или macOS!

В Windows CLI известен под несколькими именами, в том числе:

* Терминал
* Командная строка (Command Prompt)
* Windows PowerShell

В macOS CLI называется Terminal.

Однако Windows и macOS относятся к CLI как к чему-то опциональному, предназначенному лишь для продвинутых настроек.

Вместо этого Windows и macOS делают ставку на графический интерфейс (GUI) для повседневных пользователей (просто **навести и кликнуть**)

> В Linux CLI — это фундамент, и по-настоящему обойтись без него нельзя.

!!! tip "Кривая обучения CLI (чего ожидать)"

    Если вы приходите из Windows или macOS, CLI поначалу будет казаться неудобным.

    Это нормально.

    На первых порах вы, возможно, будете:

    - Копировать команды, которые не до конца понимаете  
    - Гуглить базовые задачи (установку приложений, навигацию по файлам)  
    - Совершать мелкие ошибки, временно что-то ломающие  

    Эта фаза проходит быстро.

    Довольно скоро CLI становится:

    - Быстрее, чем сценарии «навёл и кликнул»  
    - Точнее и воспроизводимее  
    - Ключевым преимуществом использования Linux  

    > Цель не в том, чтобы заучить команды, а в том, чтобы понять, как устроена система.

---

### 🐚 Оболочка (bash, zsh и т. д.)

Оболочка (shell) — это то, что интерпретирует ваши команды.

Распространённые оболочки:

* `bash` → по умолчанию в большинстве систем
* `zsh` → более настраиваемая

Думайте о ней так:

> Это язык, на котором вы разговариваете со своей системой внутри CLI.

---

### 📦 Менеджер пакетов

Менеджер пакетов — это то, как Linux устанавливает программы.

Вместо скачивания `.exe`-файлов (как в Windows):

* Вы устанавливаете из репозиториев

Примеры:

* `apt` → Debian / Devuan
* `pacman` → Arch / Artix

Пример команды в Devuan для установки приложения Nginx (используется как веб-сервер):

```bash
sudo apt install nginx
```

---

### 🧩 Дистрибутив (дистро)

Дистрибутивы (или дистро) — это разные «вкусы» Linux.

Каждый дистрибутив включает:

* Менеджер пакетов
* Инструменты по умолчанию
* Философию системы

Примеры:

* Devuan → стабильный, серверно-ориентированный, без systemd
* Artix → на базе Arch, гибкий, без systemd

> Linux — это не одна ОС; это семейство систем.

---

### ⚙️ Система инициализации (init)

Система, которая запускает всё при загрузке.

Примеры:

* `systemd` → доминирующая, централизованная
* `OpenRC`, `runit`, `s6` → более простые, модульные

Руководства RebelRx по Linux отдают приоритет:

> Системам без systemd — ради большей прозрачности и контроля.

---

### 🗂️ Структура файловой системы

Linux не использует буквы дисков вроде `C:\`.

Вместо этого:

* Всё находится под `/` (корнем)

---

### 📁 Основные каталоги

Вот главные каталоги, с которыми вы столкнётесь:

* `/` → корень всей файловой системы
* `/home` → файлы пользователей (документы, загрузки, настройки)
* `/root` → домашний каталог пользователя root
* `/etc` → общесистемные конфигурационные файлы
* `/var` → изменяемые данные (логи, базы данных, кэши)
* `/usr` → установленное пользователем ПО и системные приложения
* `/bin` → важнейшие исполняемые файлы команд (базовые системные команды)
* `/sbin` → системные бинарники (административные команды)
* `/lib` → разделяемые библиотеки, нужные бинарникам
* `/tmp` → временные файлы (часто очищаются при перезагрузке)
* `/opt` → опциональное / стороннее ПО
* `/mnt` → временные точки монтирования (ручные монтирования)
* `/media` → съёмные носители (USB-накопители, внешние диски)
* `/boot` → файлы загрузчика и образы ядра
* `/dev` → файлы устройств (интерфейсы к оборудованию)
* `/proc` → виртуальная файловая система с информацией о системе и процессах
* `/sys` → данные интерфейсов ядра и оборудования

---

### 🧠 Как об этом думать

* Есть **одна единая файловая система**
* Диски «монтируются» в каталоги (а не получают буквы)
* Всё живёт где-то под `/`

Пример:

* USB-накопитель может появиться в: `/media/usb-drive`
* Смонтированный NAS может быть в: `/mnt/nas`

> Вы не переключаетесь между дисками — вы перемещаетесь по одному дереву.

---

### 🔌 Устройства в `/dev`

В Linux:

> Аппаратные устройства представлены как файлы.

Типичные примеры:

* `/dev/sda` → первое устройство хранения (диск)
* `/dev/sdb` → второе устройство хранения
* `/dev/sda1` → первый раздел на первом диске
* `/dev/nvme0n1` → NVMe SSD
* `/dev/nvme0n1p1` → раздел на NVMe-накопителе
* `/dev/ttyUSB0` → последовательное USB-устройство
* `/dev/null` → поглощает любой ввод (чёрная дыра)
* `/dev/random` → генератор случайных чисел

Пример использования:

```bash
lsblk
```

Показывает диски вроде:

* `sda`, `sdb`, `nvme0n1` и т. д.

---

### ⚠️ Важно

Поскольку всё трактуется как файл:

* Запись не в то устройство (например, `/dev/sda`) может затереть диск
* Неправильное монтирование может скрыть или подменить содержимое каталогов

> Это мощно, но требует внимательности.

---

### 🧠 Ключевой вывод

Linux рассматривает:

* Файлы
* Устройства
* Процессы

как части единой системы.

> Поняв файловую систему, вы поймёте, как организован Linux.

---

### 🔐 Root против пользователя

* `root` → полный контроль над системой
* `user` → ограниченный доступ

Права повышаются с помощью:

```bash
sudo команда
```

## 💻 Требования к оборудованию

Одно из главных преимуществ Linux:

> Linux работает почти на чём угодно.

---

### 🧱 Минимальная реальность

Linux может работать на:

* Старых ноутбуках (10+ лет)
* Маломощных мини-ПК
* Серверах
* Современных десктопах и ноутбуках

Во многих случаях:

> Железо, «тормозящее» под Windows, снова становится полностью пригодным под Linux.

---

### ⚡ Современное оборудование

Linux масштабируется и вверх:

* Многоядерные CPU
* Топовые GPU
* Конфигурации с большим объёмом RAM

Однако совместимость зависит от:

* Драйверов GPU (NVIDIA может требовать дополнительной настройки)
* Wi-Fi-чипсетов
* Нового или нишевого оборудования

!!! warning "Совместимость GPU NVIDIA"

    GPU NVIDIA могут требовать дополнительной настройки в Linux.

    В отличие от большинства оборудования, драйверы NVIDIA не полностью открыты
    и часто требуют:

    - Ручной установки драйвера  
    - Согласования версий драйвера с вашим ядром  
    - Дополнительной настройки для Wayland или окружений рабочего стола  

    GPU AMD, напротив, обычно работают «из коробки» с открытыми драйверами.

    > Если вы новичок в Linux, оборудование AMD, как правило, даёт более гладкий опыт.

---

### 🧠 Ключевой вывод

* Windows и macOS — **экосистемы, ограниченные оборудованием**
* Linux — **гибок в отношении оборудования**

> Оборудование выбираете вы. А не вендор.

## 🧩 Философия оборудования (рекомендация: Framework)

Если покупаете новое железо, выбирайте производителей, разделяющих принципы Linux.

### 🔧 Framework Computer

Framework — одна из немногих компаний, придерживающихся:

* Права на ремонт
* Модульного дизайна оборудования
* Совместимости с Linux

Системы Framework позволяют:

* Менять компоненты вместо замены всего устройства
* Модернизировать со временем
* Никакого принудительного устаревания оборудования

> Ваше железо должно быть таким же суверенным, как и ваше ПО.

👉 Посмотрите ноутбуки и десктоп Framework: <https://frame.work/>

## 🛠️ Как на самом деле выглядит установка Linux

Установка Linux фундаментально отличается от Windows или macOS.

---

### 🧱 Windows / macOS

* Загрузить установщик
* Прокликать графический интерфейс
* Система настраивается сама
* Обязательная учётная запись
* Готово

---

### 🐧 Linux (типичный процесс)

В зависимости от дистрибутива ожидайте:

1. Загрузку в live-окружение
2. Ручное (или полуручное) разбиение дисков
3. Установку базовой системы
4. Настройку:

   * Пользователей
   * Сети
   * Загрузчика
5. Установку окружения рабочего стола (если нужно)
6. Перезагрузку в свою систему

!!! warning "Риск разбиения диска"

    Установка Linux часто требует ручного разбиения диска.

    Это один из немногих шагов, где можно случайно:

    - Удалить существующие данные  
    - Затереть другую операционную систему  
    - Неправильно настроить загрузку  

    Всегда:

    - Делайте резервную копию важных данных перед установкой  
    - Дважды проверяйте выбранные диски и разделы  
    - Понимайте, заменяете ли вы систему или ставите рядом (dual boot)  

    > Разбиение — мощный инструмент, но он предполагает, что вы знаете, что делаете.

---

### 🔧 Реальность после установки

После установки вы ещё не «закончили».

Вам предстоит:

* Установить основное ПО
* Настроить сервисы
* Настроить сеть и файрвол
* Подстроить производительность и удобство

> Linux строят, а не получают готовым.

## 🧭 Кому подходит Linux

Linux хорошо подойдёт, если вы:

* Цените приватность и независимость
* Хотите полного контроля над своей системой
* Готовы учиться и разбираться с проблемами
* Предпочитаете долгосрочную стабильность удобству

---

## 🚫 Кому он не подходит

Linux может вас разочаровать, если вы:

* Ожидаете, что всё будет «включил и работает»
* Сильно зависите от проприетарного ПО (Microsoft 365, Adobe и т. п.)
* Хотите нулевого обслуживания и нулевого обучения
