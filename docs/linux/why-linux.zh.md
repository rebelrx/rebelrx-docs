# 🐧 为什么选择 Linux

大多数人并不选择操作系统。

而是操作系统*替他们*做了选择。

* Windows → 绑定于 Microsoft 账户身份和遥测
* macOS → 绑定于 Apple 的生态系统和硬件
* 移动操作系统 → 完全封闭、与身份绑定的平台

Linux 与众不同。

> Linux 是唯一仍然允许你选择退出的主流操作系统。

## ⚔️ 为什么选择 Linux

### 🔐 控制权

Linux 让你对以下一切拥有完全的权威：

* 系统配置
* 已安装的软件
* 网络行为
* 更新策略

没有强制更新。
没有强制账户。
没有你无法审查的隐藏进程。

> 管理员是你，而不是厂商。

---

### 🧱 透明度

Linux 是开源的。

这意味着：

* 代码可以被审查
* 行为可以被验证
* 后门在这种规模下更难藏匿

对比一下：

* Windows → 闭源、不透明
* macOS → 部分开放、大体受控

---

### 🚫 没有强制的生态系统

现代操作系统（OS）平台正日益变得：

* 与账户绑定
* 依赖云端
* 与身份挂钩

而 Linux 允许你：

* 运行完全离线的系统
* 避免账户锁定
* 使用你的机器而无需任何外部验证

---

### ⚡ 高效

Linux 系统通常：

* 更快
* 资源占用更低
* 长期运行更稳定

尤其是在避开臃肿的默认配置时。

---

## ⚖️ 代价

Linux 并不是人们想象中那种"免费"。

你交换的是：

| 便利 | 控制权 |
| ------------------ | -------------- |
| 即插即用的应用 | 手动配置 |
| 厂商支持 | 自力更生 |
| 熟悉的用户体验 | 学习曲线 |

> Linux 回报那些愿意理解自己系统的人。

---

## 🧠 核心概念（术语表）

在安装 Linux 之前，你应该先理解几个关键术语。

---

### 🧬 内核（Kernel）

内核是操作系统的核心。

它位于：

* 你的硬件（CPU、内存、磁盘、GPU）
* 你的软件（应用程序、服务）

之间。Linux 内核负责：

* 与硬件通信
* 进程管理
* 内存管理
* 系统安全边界

> Linux 中的一切最终都要经过内核。

这一点很重要，因为：

* 所有 Linux 发行版共享**同一个内核基础**
* 发行版之间的区别在于内核*周围*的一切

---

### 💻 CLI（命令行界面）

一种基于文本与系统交互的方式，也被称为"终端"。

不再点击鼠标：

* 你输入命令
* 你直接通过文本终端控制系统

示例：

```bash
ls
cd /home
cp file.txt backup.txt
```

所有现代操作系统都内置了 CLI。你可能根本不知道 Windows 或 macOS 里也有它！

在 Windows 上，CLI 有几个名字，包括：

* 终端（Terminal）
* 命令提示符（Command Prompt）
* Windows PowerShell

在 macOS 上，CLI 叫做"终端"（Terminal）。

不过，Windows 和 macOS 把 CLI 当作可选项，只用于高级配置。

Windows 和 macOS 更倾向于让日常用户使用图形界面（GUI）（**指哪点哪**即可）

> 在 Linux 中，CLI 是根基，真的不是可选项。

!!! tip "CLI 学习曲线（该有什么预期）"

    如果你来自 Windows 或 macOS，一开始会觉得 CLI 很别扭。

    这很正常。

    起初，你可能会发现自己在：

    - 复制粘贴一些自己不完全理解的命令  
    - 搜索基础操作怎么做（安装应用、浏览文件）  
    - 犯些小错误，把东西暂时弄坏  

    这个阶段很快就会过去。

    用不了多久，CLI 就会变成：

    - 比"指哪点哪"更快的工作方式  
    - 更精确、更可重复  
    - 使用 Linux 的核心优势之一  

    > 目标不是背命令，而是理解系统是如何运作的。

---

### 🐚 Shell（bash、zsh 等）

Shell 是解释你所输入命令的程序。

常见的 shell：

* `bash` → 大多数系统的默认
* `zsh` → 可定制性更强

可以把它理解为：

> 你在 CLI 中与系统对话所用的语言。

---

### 📦 包管理器

包管理器是 Linux 安装软件的方式。

不再下载 `.exe` 文件（像 Windows 那样）：

* 你从软件仓库安装

示例：

* `apt` → Debian / Devuan
* `pacman` → Arch / Artix

在 Devuan 中安装 Nginx（用于网页服务）的示例命令：

```bash
sudo apt install nginx
```

---

### 🧩 发行版（Distro）

发行版（distro）是 Linux 的不同"风味"。

每个发行版都包含：

* 包管理器
* 默认工具
* 系统理念

示例：

* Devuan → 稳定、面向服务器、无 systemd
* Artix → 基于 Arch、灵活、无 systemd

> Linux 不是单一的操作系统，而是一个系统家族。

---

### ⚙️ Init 系统

在开机时启动一切的系统。

示例：

* `systemd` → 占主导地位、中心化
* `OpenRC`、`runit`、`s6` → 更简单、模块化

RebelRx 的 Linux 指南优先选择：

> 非 systemd 系统，以获得更高的透明度和控制权。

---

### 🗂️ 文件系统结构

Linux 不使用 `C:\` 这样的盘符。

取而代之的是：

* 一切都在 `/`（根目录）之下

---

### 📁 核心目录

以下是你会遇到的主要目录：

* `/` → 整个文件系统的根
* `/home` → 用户文件（你的文档、下载、配置）
* `/root` → root 用户的家目录
* `/etc` → 系统级配置文件
* `/var` → 可变数据（日志、数据库、缓存）
* `/usr` → 用户安装的软件和系统应用程序
* `/bin` → 基本命令二进制文件（基础系统命令）
* `/sbin` → 系统二进制文件（管理命令）
* `/lib` → 二进制文件所需的共享库
* `/tmp` → 临时文件（通常在重启时清空）
* `/opt` → 可选/第三方软件
* `/mnt` → 临时挂载点（手动挂载）
* `/media` → 可移动介质（U 盘、外置硬盘）
* `/boot` → 引导加载器文件和内核镜像
* `/dev` → 设备文件（硬件接口）
* `/proc` → 暴露系统/进程信息的虚拟文件系统
* `/sys` → 内核与硬件接口数据

---

### 🧠 该怎么理解

* 只有**一个统一的文件系统**
* 磁盘被"挂载"到目录中（而不是分配盘符）
* 一切都位于 `/` 之下的某处

示例：

* U 盘可能出现在：`/media/usb-drive`
* 挂载的 NAS 可能位于：`/mnt/nas`

> 你不是在切换磁盘——你是在遍历一棵树。

---

### 🔌 `/dev` 中的设备

在 Linux 中：

> 硬件设备以文件的形式呈现。

常见示例：

* `/dev/sda` → 第一个存储设备（磁盘）
* `/dev/sdb` → 第二个存储设备
* `/dev/sda1` → 第一块磁盘上的第一个分区
* `/dev/nvme0n1` → NVMe SSD
* `/dev/nvme0n1p1` → NVMe 硬盘上的分区
* `/dev/ttyUSB0` → USB 串口设备
* `/dev/null` → 丢弃一切输入（黑洞）
* `/dev/random` → 随机数生成器

使用示例：

```bash
lsblk
```

会显示这些磁盘：

* `sda`、`sdb`、`nvme0n1` 等

---

### ⚠️ 重要

正因为一切都被视为文件：

* 写错设备（例如 `/dev/sda`）可能会覆盖整块磁盘
* 挂载不当可能会遮盖或替换目录内容

> 这很强大，但需要专注。

---

### 🧠 关键要点

Linux 把：

* 文件
* 设备
* 进程

都视为同一个统一系统的组成部分。

> 一旦理解了文件系统，你就理解了 Linux 的组织方式。

---

### 🔐 Root 与普通用户

* `root` → 完全的系统控制权
* `user` → 受限访问

通过以下方式提升权限：

```bash
sudo 命令
```

---

## 💻 硬件要求

Linux 最大的优势之一：

> Linux 几乎能在任何东西上运行。

---

### 🧱 最低配置的现实

Linux 可以运行在：

* 老旧笔记本（10 年以上机龄）
* 低功耗迷你主机
* 服务器
* 现代台式机和笔记本

在许多情况下：

> 在 Windows 上感觉"卡顿"的硬件，到了 Linux 上又变得完全可用了。

---

### ⚡ 现代硬件

Linux 同样可以向上扩展：

* 多核 CPU
* 高端 GPU
* 大内存配置

不过，兼容性取决于：

* GPU 驱动（NVIDIA 可能需要额外配置）
* Wi-Fi 芯片组
* 新出的或小众的硬件

!!! warning "NVIDIA GPU 兼容性"

    NVIDIA GPU 在 Linux 上可能需要额外配置。

    与大多数硬件不同，NVIDIA 驱动并非完全开源，通常需要：

    - 手动安装驱动  
    - 让驱动版本与你的内核匹配  
    - 为 Wayland 或桌面环境做额外配置  

    相比之下，AMD GPU 通常凭借开源驱动即可开箱即用。

    > 如果你是 Linux 新手，AMD 硬件通常体验更顺滑。

---

### 🧠 关键要点

* Windows 和 macOS 是**受硬件约束的生态系统**
* Linux 则**对硬件保持灵活**

> 硬件由你选择，而不是由厂商决定。

---

## 🛠️ 一次 Linux 安装到底是什么样子

安装 Linux 与安装 Windows 或 macOS 有着根本的不同。

---

### 🧱 Windows / macOS

* 启动安装程序
* 在图形界面里一路点击
* 系统自动配置
* 必须注册账户
* 完成

---

### 🐧 Linux（典型流程）

依发行版而定，你可以预期：

1. 启动进入 live 环境
2. 手动（或半手动）为磁盘分区
3. 安装基础系统
4. 配置：

   * 用户
   * 网络
   * 引导加载器
5. 安装桌面环境（如需要）
6. 重启进入你的系统

!!! warning "磁盘分区风险"

    Linux 安装通常需要手动分区。

    这是少数几个你可能不小心：

    - 删除现有数据  
    - 覆盖另一个操作系统  
    - 配错引导设置  

    的步骤之一。请务必：

    - 安装前备份重要数据  
    - 反复核对所选的磁盘和分区  
    - 弄清楚自己是在整盘替换还是做双系统  

    > 分区很强大——但它的前提是你清楚自己在做什么。

---

### 🔧 装完之后的现实

安装完成后，你还没有"搞定"。

你还要：

* 安装核心软件
* 配置各项服务
* 设置网络和防火墙
* 调优性能和易用性

> Linux 是自己搭建出来的，不是别人递到你手上的。

---

## 🧭 Linux 适合谁

如果你符合以下情况，Linux 会非常适合你：

* 重视隐私和独立性
* 想要对系统的完全控制权
* 愿意学习和排查问题
* 偏好长期稳定而非一时便利

---

## 🚫 不适合谁

如果你符合以下情况，Linux 可能会让你抓狂：

* 期望一切都即插即用
* 严重依赖专有软件（Microsoft 365、Adobe 等）
* 想要零维护、零学习

---

## 🧠 最后的思考

大多数操作系统都在走向：

* 强制身份绑定
* 平台管控
* 削减用户自主权

Linux 是最后几个仍然满足以下条件的环境之一：

> 用户依然是主人。

但前提是，你要有意识地选择它。
